# Research & Decisions — Spec 034 (D1–D31)

Each decision: **Decision · Rationale · Alternatives**. Grounded in the legacy evidence + current patterns (see `plan.md` grounding note).

## Baseline & count
- **D1 — baseline count 103.** Decision: confirmed (verified `find public -name '*.html' | wc -l` = 103; build green). Rationale: Spec-032 freeze; no app source changed since. Alt: none.
- **D2 — count target 113.** Decision: 103 + 5 pairs (+10) = 113. Rationale: Spec-033 envelope 034 row. Alt: fold some into existing pages — rejected (Control items have no existing surface; standalone is the grounded call).
- **D3 — 5 new page bases.** Decision: `messages`, `leads`, `tasks`, `announcements`, `time-converter`. Rationale: the 5 Control «قريبًا» items. Alt: none.
- **D4 — 5 nav flips only.** Decision: flip exactly those 5 `planned→implemented`; no other nav item changes. Rationale: scope boundary. Alt: none.

## messages
- **D5 — layout.** Decision: two-pane shell — inbox list (authored conversations) + a default open thread panel (authored bubbles) inline; conversation rows are `data-drawer="msg-<id>"` → read-only thread sheet. Rationale: static-per-page (no dynamic thread switching engine); the drawer clone path shows any thread read-only. Alt: JS-swapped active thread — rejected (needs a stateful engine; dishonest w/o backend).
- **D6 — compose fields.** Decision: `message` (textarea) + a gated attachment affordance (btn-secondary `data-disabled-reason`, **no `type=file`**). Rationale: legacy composer is AJAX (not captured); minimal honest compose. Alt: rich editor — rejected (no engine).
- **D7 — Send/Reply gate.** Decision: a `btn-primary` `data-disabled-reason` (`msg.reason.backend`) — no message appended, no read-state flip. Create-Group/Add-Member Save = same gate; image = inline gate. Rationale: no message-delivery engine. Alt: fake "sent" — forbidden.

## leads
- **D8 — layout.** Decision: `pageHeader` + `summaryCards` (authored KPIs) + `filterBar` (status/source/search) + a lead list + a lead-detail `data-drawer` + a Create-Request `formDrawer`. Rationale: mirrors the legacy KPI-dashboard + filtered-list + detail-modal shape and the current display-board precedent. Alt: table.js sessionsModule — usable, but a `cardGrid`/list + filterBar is lighter and matches.
- **D9 — fields.** Decision: detail drawer = notes-log `sheetRow`s + **Add-Notes** (`note` textarea) + **Change-Status** (`status` select, 9 options: duplicated/pending/contacting/no-response/qualified/scheduled/trial-taken/trial-missed/teacher); **Create-Request** = the grounded ~19 fields (first/last name, email, phone, friends_number, classes_Duration, hear_from, classes_count, gender, age, parent_age, language, timezone, trial_date, trial_time, coupone_code[text-code], country, course_name, note). Rationale: verbatim from `management-new-requests(-create)`. Alt: trim fields — kept full for fidelity; **no money field** (courses by name).
- **D10 — convert/assign/save gate.** Decision: Create Submit, Add-Notes Save, Change-Status Update, Convert, Assign = `data-disabled-reason` gates; **no row added, no status chip flip**. Rationale: no CRM engine. Alt: fake convert — forbidden.

## tasks
- **D11 — board vs list.** Decision: a display-only **board** (status columns) + a per-staff summary table + a KPI strip; **no drag**. Rationale: legacy is a task board with per-staff counts; board reads best; drag needs a persistence engine. Alt: list-only — less faithful; kept board (static columns).
- **D12 — create/edit fields.** Decision: title, description (textarea), assignee (select), status (select), priority (select), due-date (text), section (select) — authored safe fields grounded in the captured KPI/per-staff columns (board/create form not captured — evidence gap). Rationale: minimal honest task form. Alt: invent more fields — rejected (grounding discipline).
- **D13 — status/move/assign gate.** Decision: Create/Edit Save, Assign, Move, Add-Section = gates; board has **no working drag** (no fake move/status). Rationale: no task engine. Alt: fake move — forbidden. "Average" column = authored literal (no compute).

## announcements
- **D14 — layout.** Decision: `pageHeader` + announcements list (`cardGrid`, audience/channel/status chips) + an inline **compose** form + a **preview** card + a recipient display. Rationale: mirrors `management-public-advertisement` (compose + recipient tables). Alt: compose in a drawer — inline reads better for a composer; either is fine.
- **D15 — compose fields.** Decision: message (textarea), channel toggles `type[]` (Advertisement/WhatsApp checkboxes), `private` (checkbox), `expire_at` (date text), audience category multi-selects (teacher + student), country/hours/language (selects), **media = inline gate** (no `type=file`). Schedule = a display/gate. Rationale: verbatim from the legacy compose form. Alt: drop channels — kept (grounded), but WhatsApp send = gate.
- **D16 — publish/send gate.** Decision: Publish/Send = `data-disabled-reason`; WhatsApp/channel delivery + media = gates; **no fake published**. Rationale: no broadcast/delivery engine (+ integration creds owned by Spec 040). Alt: fake publish — forbidden. **Boundary**: the System-Notification *settings* form stays in `settings.html` (Spec 031/040) — not duplicated here.

## time-converter
- **D17 — computation approach.** Decision: a page-scoped **`initTimeConverter()` IIFE added to `enhance.js`** (mirroring `initTabs`/`initWizard`), guarded by the converter DOM (`[data-time-converter]`), using **native `Intl.DateTimeFormat(locale, { timeZone, ... })`** + `Date` to recompute the output on any control change. **No new global `data-*` dispatch hook, no storage key, no dependency.** Rationale: a real converter needs runtime, which lives only in the shared `enhance.js`; the page-scoped-init precedent keeps it inert on all other pages and adds no new declarative cross-page hook. This is the ONE justified touch to a shared file. Alt A: a static baked "now across zones" board (zero JS) — rejected as the spec requires interactive "changing input updates output"; kept as the fallback if the init is disallowed. Alt B: a new dependency (moment-timezone) — forbidden.
- **D18 — timezone list / quick chips.** Decision: an authored IANA list in `control-center.js` (curated subset by region: Africa/Americas/Asia/Europe/Oceania) + common-academy quick chips (Cairo `Africa/Cairo`, Riyadh `Asia/Riyadh`, Dubai `Asia/Dubai`, London `Europe/London`, New York `America/New_York`, …). Rationale: the browser's own `Intl` tz database does the math; the list is just labels. Alt: fetch tz data — forbidden (no network).
- **D19 — no-backend/no-dependency proof.** Decision: smoke asserts 0 external requests on `time-converter` load + interaction; `package.json` 0-diff; native `Intl` only; no `<script src>` added. Rationale: the tool must be provably offline. Alt: none.
