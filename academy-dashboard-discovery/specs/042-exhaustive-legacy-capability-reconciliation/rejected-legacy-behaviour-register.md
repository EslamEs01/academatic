# Spec 042 — Rejected Legacy Behaviour Register

**Purpose**: the single canonical list of every legacy behaviour the current product REFUSED —
dispositions `REJECTED_SECURITY` / `REJECTED_PRIVACY` / `REJECTED_NO_FAKE` / `REJECTED_PAY_FREE`
plus every "deliberately refused / must never be fixed back" finding recorded in the C01–C15
cluster-audit prose and in `privacy-and-sensitive-data-findings.md`.

**Sources**: `cluster-audits/C01-audit.md … C15-audit.md`, `privacy-and-sensitive-data-findings.md`,
`protected-test-carryover.md`. Rows are DEDUPLICATED across clusters — each row lists the cluster
capIds / privacy-row ids it consolidates. Evidence paths resolve relative to
`academy-dashboard-discovery/`. Documentation-only; nothing under `app/**` was touched.

**Standing rule for ALL rows**: a future spec may re-open a row ONLY by an explicit supersession
that names this register id, cites new evidence, and proves the refusal's guard still holds — and
the rows below marked **NEVER** may not be re-proposed by any spec, ever. The protected-test
guarantees cited in the Guard column are inherited per `protected-test-carryover.md` §1
("Spec 042 supersedes NOTHING") and may only change via a declared supersession with mutation proof.
