## Required conclusions

1. **How did the legacy family app let the guardian inspect children/students?** Scattered, form-driven: a Select-Student dropdown + Submit on the history filter, per-child×course rows on the subscriptions list (History/Feedback buttons), and a Student Name column on the today table. There was NO per-child hub — and the profile page returned a **500 error**.
2. **What did the legacy child/student history/profile view show?** History = a table of class sessions (date/time, labeled status chip, teacher, subject, duration, per-row Class History action). Profile = broken (500). So legacy proved the DEMAND (per-child inspection) but never delivered a working per-child surface.
3. **Best way to rebuild as `family-child.html`?** Exactly as planned: ONE page, five baked panels (identity+chip · course/group/teacher · today/next · attendance mini-trio + progress · latest note · homework/materials lines · history+profile gates), five REAL links from home child cards, `#child=stX` deep links replacing dropdown+submit, default st1. This unifies what legacy scattered across 3 tables + 1 broken page. **Confirmed — no change.**
4. **How did the legacy teacher dashboard organize schedule/students/workflow?** Home = short recent-sessions-of-a-student list; Schedule = dense hour×day grid; Students = action-heavy roster table; Monthly plans = per-student report table; Tasks = KPI tiles + chart + staff table; outcome updates were reached through the **salary** report surface (coupling).
5. **What we keep from the teacher legacy idea:** student-follow-up-centric core; recent-sessions-with-labeled-status as the landing signal; the task-state taxonomy (feeds «مهام مفتوحة»); duration/status chips; per-day teaching view.
6. **What we avoid from the teacher legacy UI:** the 12AM-first hour grid; charts; the outcome→salary coupling (pay-free law); Chat (backendRequired); marketing heroes inside logged-in pages; unlabeled "New" pill noise.
7. **How does the admin dashboard rhythm guide the compact homes?** `academy-dashboard.png` maps 1:1 onto the 7-band recipe (welcome→header, overview→KPI row, today table→now band, report cards→preview/tiles, gated card→availabilityChip gates, UI-states row→truthful empties). The role homes re-express this rhythm in `.pt-*` tokens with role accents — never admin selectors.
8. **Do any Spec 018 decisions need to change?** **No.** Every decision is confirmed, three of them STRENGTHENED: family-child fills a surface legacy left broken (500); the compact recipe bans an anti-pattern legacy demonstrably had (library heroes, endless grids); the KPI row has a legacy-native precedent (the tasks tiles). One honest note: the legacy tasks page used 5 tiles; our recipe pins 4 per the approved admin reference — deliberate, recorded here.
