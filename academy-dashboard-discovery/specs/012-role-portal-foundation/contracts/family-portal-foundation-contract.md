# Contract: Family Portal Foundation (Spec 012)

**Status**: Binding · The fam1 guardian foundation page — deep dashboard = Spec 014. References FR-002/FR-004/FR-005; US3; research D3/D9.

## 1. Composition

1. **Guardian welcome** — fam1's guardian, calm trustworthy tone.
2. **Children overview** — fam1's five fixture children as friendly cards (avatar accent, name, level/status chip); the multi-child pattern visibly present (a baked child-switcher preview or clearly-labeled foundation affordance — never a fake control).
3. **Today's sessions preview** — the children's fixture sessions today, card list.
4. **Attendance/progress preview** — display-only roll-up from existing outcome/attendance fixtures for the children (labeled chips, no computed scores).
5. **Teacher notes preview** — fixture-authored note cards anchored in the legacy per-session Class-Summary/Homework concept (display-only).
6. **Planned cards** — billing/finance (honest planned/backendRequired; the DEFAULT is a planned card — an "admin demo"-labeled link to the fixture finance shell is permitted ONLY if review finds it clearer) · feedback meetings · subscriptions/plans.
7. **Spec-014 note** — the deep family dashboard arrives in Spec 014.

## 2. MUST NOT

No live-looking payment/billing functionality or amounts presented as payable; no fake child-switch behavior; no admin chrome; no dense tables; no legacy cloning; no confusing parent-hostile density.

**Acceptance (binding):**
1. **Given** the page, **When** the children overview renders, **Then** all five fam1 children appear from fixtures and the multi-child pattern is honest.
2. **Given** the billing surface, **When** inspected, **Then** it is a labeled planned/backendRequired card (or the explicitly labeled admin-demo link), never a payment affordance.
3. **Given** the whole page in AR+EN, **When** reviewed, **Then** it reads calm/clear/child-centered, mobile-first, not admin UI.
