# Docs Guard

Read project instructions first. Treat documentation as testable claims: verify
every route, command, file path, count, owner, task state, contract reference,
and implementation-report statement against the current repository. Reconcile
contradictions; do not guess or copy a previous agent's claim. Remove filler,
machine paths, secrets, and examples that cannot run. Check internal links and
keep the SpecKit status, contracts, and implementation evidence aligned.

This guard reviews documentation claims; it does not replace code, security,
test, or visual review.
